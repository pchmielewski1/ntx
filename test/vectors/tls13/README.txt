TLS 1.3 (RFC 8446) vectors, generated by test/scripts/tls13_ref.py (python3 plus the
`cryptography` package). The script is an independent implementation, written
separately from src/net/ntx_tls13.c, so the two cannot share a bug.

  kat.txt            "key=hex" lines read by test/t_tls13.c:
                       - key schedule (ECDHE, handshake and application traffic
                         secrets, keys, IVs, KeyUpdate)
                       - HKDF-Expand-Label cases
                       - Finished
                       - record protection (including padding and large sequence numbers)
                       - ClientHello, ServerHello, EncryptedExtensions, Certificate,
                         CertificateVerify and Finished messages
  leaf_p256.der, key_p256.pem
                     self-signed ECDSA P-256 certificate "nanotorrent-tls13-fixture" and its key
  leaf_rsa.der, key_rsa.pem
                     self-signed RSA-2048 certificate "nanotorrent-tls13-fixture" and its key
  leaf_p256.pin.hex, leaf_rsa.pin.hex
                     SHA-256 of each certificate's SubjectPublicKeyInfo (the SPKI pin,
                     as printed by test/scripts/pin_from_der.py)

The certificates and keys are inputs of tls13_ref.py (it reads them, it does not
generate them). The keys are test-only and public.

The other inputs are the RFC 7748 test keys (Alice/Bob) and a fixed ClientHello random,
so regenerating kat.txt gives byte-identical output except for the CertificateVerify
signatures, which are randomised.

The frozen server streams for the end-to-end handshake replay are in
test/fixtures/tls/ (see test/fixtures/README.md); they are replayed by
test/t_tls_golden.c.
